# Ghost Chat Cleaner

[English](README.md) | [한국어](README.ko.md)

Ghost Chat Cleaner는 로컬 `codex-dev.db`의 대화 목록에 남은 오래된 ChatGPT 항목을 검토하고, 안전 검사를 통과한 선택 항목을 제거하는 데스크톱 유틸리티다. 로컬 목록을 로그인한 ChatGPT 웹 계정과 대조해 검토할 항목을 표시하며, 정리 전에 백업을 생성하고 검증한다.

정리는 이 기기의 `local_thread_catalog` 테이블에서만 항목을 제거한다. ChatGPT 서버의 대화는 삭제하지 않는다. 웹 응답 `404`는 확인한 계정과 조회 조건에서 대화를 이용할 수 없다는 뜻이며, 대화가 삭제되었다는 증거는 아니다.

인터페이스는 한국어이며, 아래 설명에서는 실제 버튼 표기를 그대로 사용한다. 이 프로젝트는 독립 프로젝트이며 OpenAI의 공식 유틸리티가 아니다.

## 소스에서 시작하기

Git, Cargo가 포함된 Rust 도구 모음, 해당 운영체제의 네이티브 C/C++ 빌드 도구가 필요하다. macOS에서는 Xcode 명령줄 도구를, Windows에서는 MSVC 도구 모음과 Visual Studio C++ 빌드 도구를 사용한다. Linux에 필요한 개발 라이브러리는 [빌드 워크플로](.github/workflows/release-build.yml)에 나와 있다.

```sh
git clone https://github.com/AidALL/Ghost-Chat-Cleaner.git
cd Ghost-Chat-Cleaner
cargo run --locked --release -- --demo
```

데모는 고정된 가상 대화와 모의 결과로 GUI를 연다. 브라우저를 열거나 실제 대화 목록 데이터베이스와 증거 로그를 읽지 않으며, 실제 프로세스 목록을 조사하거나 실제 정리를 수행하지 않는다. 화면 상단에 `예시 데이터`가 표시된다.

실제 대화 목록을 확인하려면 데모를 닫고 `--demo` 없이 실행한다.

```sh
cargo run --locked --release
```

일반 실행 모드는 실제 로컬 대화 목록과 로그인한 브라우저 세션을 사용한다. 목록을 불러오는 작업은 읽기 전용이다. 정리하려면 항목을 별도로 선택하고 확인 창에서 정리를 승인해야 한다. 화면 없이 조회나 정리를 실행하는 CLI는 제공하지 않는다.

이 절차에는 배포된 실행 파일이 필요하지 않다. 직접 포터블 앱을 만들려면 [빌드와 패키징](#빌드와-패키징)을 참조한다. 저장소 워크플로는 CI 산출물을 생성하며 GitHub Release를 만들지 않는다.

## 운영체제와 계정 범위

| 운영체제 | 구현된 동작 | 로컬 실행 검증 |
| --- | --- | --- |
| macOS Apple silicon | 조회 및 안전 검사 후 대화 목록 정리 | 저장된 Edge 로그인, 실제 데이터 읽기 전용 대조, 종료와 재실행 확인 |
| macOS Intel | 조회 및 안전 검사 후 대화 목록 정리 | 로컬에서 실행 검증하지 않음 |
| Windows | 조회 및 안전 검사 후 대화 목록 정리 | 로컬에서 실행 검증하지 않음 |
| Linux | 조회 전용이며 정책상 정리 비활성화 | 로컬에서 실행 검증하지 않음 |

macOS Apple silicon 검증은 2026-09-07에 수행했다. 로그인 정보를 다시 입력하지 않고 저장된 인증 상태를 복원했으며, 웹에 존재하는 항목이 선택되지 않도록 보호되는 것을 확인했다. 실제 정리는 수행하지 않았고, 정리 보호 장치는 가상 테스트 데이터로 검증한다. 이는 시험한 빌드와 계정에 대한 근거이며 모든 운영체제나 향후 ChatGPT 버전을 보장하지 않는다. 자세한 범위는 [브라우저 검증 기록](docs/browser-contract.md#verification-limit)에 나와 있다.

웹 대조에는 개인 ChatGPT 계정과 시스템 기본 HTTPS 브라우저로 등록된 지원 대상 Chrome, Edge 또는 Chromium 네이티브 설치가 필요하다. 지원하지 않는 기본 브라우저는 거부하며, 앱이 임의로 다른 브라우저를 선택하지 않는다. Workspace 계정이나 계정 식별이 모호한 경우에는 진행을 차단한다. 수집기는 문서화되지 않은 ChatGPT 웹 엔드포인트를 사용하므로 웹사이트 변경에 따라 수정이 필요할 수 있다.

## 대화 목록 확인하기

1. `대화 목록 파일`에 `codex-dev.db` 경로를 입력하거나 `자동 찾기`를 누른다. 후보가 여러 개라면 사용할 파일을 선택한다. `불러오기`를 눌러 읽기 전용으로 확인한다.
2. 필요하면 `추가 설정`을 펼치고 삭제 기록 파일이나 폴더 경로를 한 줄에 하나씩 입력한다. 명시적으로 입력한 경로만 검색한다. 로컬 삭제 기록이 없다면 빈칸으로 둔다.
3. 앱은 시작할 때 저장된 로그인을 복원하려고 시도한다. 연결되지 않았다면 `로그인`을 누르고 해당 대화 목록과 같은 개인 ChatGPT 계정으로 로그인한다. 비밀번호와 인증 코드는 브라우저의 공식 로그인 화면에만 입력한다.
4. `목록 확인`을 누른다. macOS에서는 전용 로그인 브라우저에 정상 종료를 요청하고, 성공적으로 종료될 때까지 최대 30초 기다린 후 계속한다. Windows와 Linux에서는 사용자가 전용 브라우저를 직접 닫은 뒤 계속한다. 인증과 대조는 동일한 저장 프로필을 다시 사용한다.
5. 로컬 대화 제목과 결과를 검토한다. 목록이 아직 로드되지 않았다면 `목록 확인`이 입력한 경로 또는 유일하게 발견된 후보를 불러올 수 있다. 후보가 여러 개라면 선택이 필요하다. 인증에 성공하면 이미 로드된 조회 결과도 자동으로 대조한다.

자동 찾기는 입력한 경로, `$CODEX_HOME/sqlite/codex-dev.db`, `$HOME/.codex/sqlite/codex-dev.db`를 확인한다. 환경 변수가 설정되지 않았다면 해당 후보는 제외한다. 경로는 언제든 직접 입력할 수 있으며, 자동 찾기 자체는 데이터베이스 내용을 조회하지 않는다.

### 결과 이해하기

로컬 분류와 웹 결과는 서로 다른 내용을 나타낸다.

| UI 표기 | 의미 |
| --- | --- |
| `삭제 기록` | 일치하는 로컬 삭제 표시를 찾았다는 뜻이다. 웹에 존재하면 이 항목도 보호한다. |
| `검토 필요` | 수동 검토가 필요하다. 항목을 선택하기 전에 해당 행의 `확인`을 체크한다. |
| `유지` | 현재 검사 결과에 따라 보존하는 항목이며 선택할 수 없다. |
| `웹에 있음` | 인증된 웹 조회에서 대화를 찾았다. 해당 항목의 정리를 차단한다. |
| `조회 불가` | 보호 조건을 적용한 직접 조회에서 검증된 계정과 조회 조건으로 대화를 이용할 수 없었다. 삭제를 입증하지는 않는다. |
| `미확인` | 허용할 수 있는 웹 근거가 없다. 해당 항목의 정리를 차단한다. |

수집기는 먼저 활성 대화, 별표 표시 대화, 보관된 대화의 메타데이터에서 요청한 ID를 찾는다. 목록에 존재하면 항목을 보호하지만, 목록에 없다는 사실만으로 대화의 부재를 입증하지는 않는다. 아직 확인되지 않은 ID만 직접 조회한다. JSON `404`를 조회 불가로 받아들이려면 해당 행이 검증된 개인 사용자와 연결되어 있고, 프로젝트나 작업 디렉터리 맥락이 없어야 한다. 또한 동일한 로컬 호스트에 속하는 별도 양성 대조군 ID에서 직접 JSON `200` 응답을 확인해야 한다. 그 양성 대조군이 없는 호스트의 부재 근거는 허용하지 않는다.

로컬 삭제 근거가 없는 일반 행도 위 조회 불가 조건을 통과하면, 로컬 누락 플래그가 거짓이더라도 `검토 필요`로 분류된다. 누락 플래그만으로는 삭제를 입증하지 않는다. 웹에 존재하는 행, 프로젝트 맥락이 있는 행, 다른 계정의 행, 검증할 수 없는 행은 정리 조건을 통과할 수 없다. 계정 불일치, 불완전한 응답, 요청 제한, 결과 불일치가 있으면 정리를 차단한다.

대조 근거는 5분 후 만료되며 재조회하거나 원본이 바뀌면 무효화된다. 로그인 연결만으로 정리가 허용되지는 않는다. 버전별 근거 형식과 검증 세부 사항은 [관찰된 브라우저 계약](docs/browser-contract.md)을 참조한다.

## 선택한 로컬 항목 정리하기

정리는 Windows와 macOS에서만 가능하며, 대화 목록과 웹 검사를 먼저 통과해야 한다.

1. 정리 가능한 각 항목을 검토하고 `검토 필요` 행의 검토 확인을 마친 뒤 제거할 항목을 선택한다.
2. `백업 위치`를 눌러 팝업에서 폴더 경로를 확인하거나 수정한다. 아래 백업 폴더 규칙을 따른다.
3. 연결된 브라우저는 열어 둔 채 ChatGPT 데스크톱 앱과 앱의 보조 프로세스를 직접 종료한다. Chrome 확장 프로그램과 Codex CUA 프로세스는 계속 실행해도 된다. 항목이 선택되어 있으면 데스크톱 앱 상태를 조용히 자동 확인한다. 실행 중이거나 상태를 알 수 없으면 정리를 차단한다. 상태를 알 수 없으면 `다시 확인`을, 웹 대조를 갱신해야 하면 `목록 확인`을 누른다.
4. 창 하단에 고정된 큰 `선택 N개 정리` 버튼을 누르면 로컬 대화 목록 변경과 백업을 설명하는 확인 창이 열린다. `취소`를 누르면 선택을 유지한 채 돌아가며, `N개 정리`를 누르면 진행한다. 선택, 검토 확인, 원본, 백업 폴더, 웹 대조가 바뀌면 열린 확인 창은 무효화된다. 정리 승인 직전에도 전제 조건을 다시 확인한다.
5. 작업이 끝날 때까지 앱을 열어 둔다. 백업 경로와 함께 SHA-256 해시, 정리 전후 행 개수 등 표시된 처리 결과를 보관한다. 처리 결과 내보내기나 자동 복원 명령은 제공하지 않는다.

| 운영체제 | 백업 폴더 조건 |
| --- | --- |
| Windows | 이미 존재하고 쓰기 가능한 폴더이며, 정규화한 실제 경로가 조회한 데이터베이스의 부모 폴더와 같아야 한다. 다른 폴더는 거부한다. |
| macOS | 이미 존재하고 쓰기 가능하며 그룹과 기타 사용자 권한이 없는 폴더이거나, 이미 존재하는 쓰기 가능한 부모 폴더 바로 아래의 새 폴더여야 한다. 앱이 새 폴더를 비공개 권한으로 생성한다. |

심볼릭 링크와 폴더가 아닌 경로는 거부한다. 없는 중간 부모 폴더는 생성하지 않는다.

정리 작업은 데이터를 바꾸기 전에 웹 대조를 다시 수행한다. 정리 엔진은 원본과 프로세스 상태를 재검사하고, 전체 SQLite 백업을 생성하고 검증한 후, 보호 조건이 적용된 트랜잭션에서 선택한 `(host_id, thread_id)` 식별자만 제거한다. 커밋 전에 행 개수, 무결성, 외래 키, 프로세스 상태를 확인하고 커밋 후 상태도 검증한다. 커밋 또는 검증 결과가 불확실하면 보존된 백업을 바탕으로 조사해야 한다. 아무것도 바뀌지 않았다고 가정하거나 즉시 재시도하지 않는다. 구현은 [src/repair.rs](src/repair.rs)에 있다.

### 백업에서 복구하기

백업은 대화 목록 외의 테이블도 포함하는 전체 데이터베이스 스냅샷이다. 복원하면 백업 이후의 다른 변경 사항이 사라질 수 있다. 복원 버튼은 제공하지 않는다.

복구 전에 ChatGPT, 이 유틸리티, 데이터베이스를 사용하는 다른 모든 앱을 닫는다. SQLite 상태를 일관되게 다루는 방식으로 현재 상태를 백업하고, 원래 검증된 백업도 보존한다. 백업 무결성과 처리 결과에 표시된 해시를 확인한다. SQLite 복구에 익숙한 담당자가 백업·복원 기능으로 복구한 뒤 무결성을 확인하고 앱을 다시 연다. `-wal` 또는 `-shm` 보조 파일을 무시한 채 `.db` 파일만 덮어쓰거나, 간편한 해결책으로 보조 파일을 삭제하지 않는다. 관련 복구 고려 사항은 SQLite의 [Online Backup API](https://sqlite.org/backup.html)와 [WAL 수명 주기](https://sqlite.org/wal.html#the_wal_file)에 설명되어 있다.

## 저장된 로그인과 개인정보

앱은 현재 기본 브라우저 제품에 맞는 전용 영구 프로필을 생성한다. 평소 사용하는 프로필에 연결하거나 그 쿠키를 복사하지 않는다. 사용자가 로그인하는 브라우저는 디버깅·자동화 플래그 없이 시작한다. 대조할 때는 로그인 브라우저가 성공적으로 종료된 후, 임의의 루프백 전용 디버깅 포트로 전용 프로필을 다시 연다.

브라우저가 관리하는 쿠키와 세션 상태는 해당 프로필에 남는다. 인증 전용 검사는 인증 여부를 나타내는 불리언 값만 반환한다. 대조는 필요한 필드만 남긴 계정 식별 정보, 요청한 대화 ID, ID별 근거, 양성 대조군 ID를 반환한다. 인증과 메타데이터는 브라우저에서 실행되는 코드가 처리하며, 네이티브 Rust 앱은 쿠키 저장소를 읽거나 토큰, 비밀번호, 인증 헤더, 대화 본문을 받지 않는다. 표시되는 제목은 로컬 대화 목록에서 가져온다. 대화 직접 조회는 응답 본문을 파싱하지 않고 취소하지만, 일부 바이트가 이미 브라우저에 도착했을 수 있다. 루프백 디버깅은 여전히 높은 권한의 로컬 접근이며, 같은 운영체제 사용자 권한으로 실행되는 악성 프로그램으로부터 보호하지는 않는다.

저장된 프로필은 실행 파일과 별도로 `browser-profiles/<product>` 아래에 보관한다. `<product>`는 `edge`, `chrome`, `chromium` 중 하나다.

| 운영체제 | 앱 데이터 기본 경로 |
| --- | --- |
| macOS | `$HOME/Library/Application Support/Ghost Chat Cleaner` |
| Windows | `%LOCALAPPDATA%\Ghost Chat Cleaner` |
| Linux | 절대 경로인 `$XDG_DATA_HOME/ghost-chat-cleaner`, 그렇지 않으면 `$HOME/.local/share/ghost-chat-cleaner` |

앱을 정상 종료하면 앱 소유 브라우저를 닫고 로그인은 보존한다. 재실행할 때 기존 프로필을 다시 인증하며, 준비 상태 마커는 현재 인증의 증거가 아니다. `연결 해제`를 누르면 대조 근거를 무효화하고, 브라우저 종료를 확인한 뒤 활성 앱 소유 프로필을 삭제한다. 활성 세션이 없다면 현재 기본 브라우저 제품의 저장된 프로필을 대상으로 한다. 다른 제품의 프로필, 일반 브라우저 프로필, 대화 목록 데이터는 변경하지 않는다.

전용 로그인 브라우저를 닫으면 앱은 사용자가 `목록 확인`을 누를 때까지 기다린다. 대조 브라우저의 종료가 확인되면 연결과 대조 근거를 해제하며 브라우저를 자동으로 다시 열지 않는다. 브라우저 탭이나 대상이 사라졌다면 사용자가 확인 작업을 실행한 후 `로그인`으로 다시 연결할 수 있다. 일반적인 대조 실패에서는 수동 재시도를 위해 연결을 유지하지만, 인증이 만료되면 다시 로그인해야 한다.

프로필 충돌이나 안전하지 않은 저장 상태가 있으면 재사용을 차단한다. 오류를 우회하려고 `.ghost-chat-cleaner-browser-active` 또는 별도 `browser-locks/<product>.lock` 파일을 수동으로 제거하지 않는다. 복구 규칙과 정확한 소유 범위는 [브라우저 수명 주기와 프로필 계약](docs/browser-contract.md#browser-login-lifecycle)에 설명되어 있다.

## 목록 호환성과 로컬 근거

읽기를 지원하려면 `local_thread_catalog` 테이블에 텍스트 친화도(text affinity)를 가진 `host_id`, `thread_id`, `display_title`, `source_kind` 열이 있어야 한다. `source_kind = 'chatgpt'`인 행만 표시한다.

정리에는 호환되는 `project_id`, `cwd`, `missing_candidate`, `source_recency_at` 열과 정확히 `(host_id, thread_id)` 순서인 기본 키가 추가로 필요하다. 대상 테이블에 트리거가 없어야 하며, 해당 테이블을 참조하거나 해당 테이블에서 다른 테이블을 참조하는 외래 키도 없어야 한다. 알 수 없거나 호환되지 않는 스키마는 읽기 전용으로 유지하거나 미지원 스키마 결과를 반환한다. 프로젝트·작업 디렉터리 맥락이 있는 행, 잘못된 식별자나 신뢰할 수 없는 분류 필드가 있는 행은 보존한다. 지원 여부는 검사한 구조를 기준으로 하며 특정 ChatGPT 또는 Codex 버전의 지원을 약속하지 않는다. [src/catalog.rs](src/catalog.rs)를 참조한다.

로컬 근거에는 경계가 구분된 정확한 스레드 식별자와, 대소문자를 구분하며 경계가 구분된 `conversation_deleted` 또는 `conversation deleted` 표시가 같은 줄에 있어야 한다. 지원하는 텍스트 확장자는 `.log`, `.txt`, `.json`, `.jsonl`, `.ndjson`이다. 최신성, 바이트 수, 탐색 범위, 경로 검사가 검색을 제한하며 심볼릭 링크와 안전하지 않은 경로 변경은 거부한다. 여러 호스트가 공유하는 스레드 ID는 호스트를 구분할 수 없는 근거로 자동 확정하지 않는다. 이러한 표시는 로컬 휴리스틱이므로 검토가 필요하다. [src/evidence.rs](src/evidence.rs)를 참조한다.

## 빌드와 패키징

체크아웃한 저장소에서 rustfmt와 Clippy가 포함된 Rust를 사용하며, 수집기 테스트 데이터 검증에는 Node.js가 필요하다.

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
node --test tests/web_collector.test.cjs
cargo build --locked --release
```

테스트는 가상 데이터와 모의 프로세스 확인기를 사용한다. 릴리스 빌드는 macOS/Linux에서 `target/release/ghost-chat-cleaner`, Windows에서 `target/release/ghost-chat-cleaner.exe`를 생성한다. SQLite는 [Cargo 의존성 설정](Cargo.toml)을 통해 함께 빌드된다.

대상 운영체제에서 빌드한 뒤 해당 패키징 스크립트를 실행한다. 의존성 고지를 구성하려면 Python 3과 캐시된 Cargo 의존성이 필요하다.

```sh
# macOS: .app.zip 압축 파일 생성
bash scripts/package-macos.sh

# Linux: .tar.gz 압축 파일 생성
bash scripts/package-linux.sh
```

```powershell
# Windows: .zip 압축 파일 생성
./scripts/package-windows.ps1
```

스크립트는 이미 존재하는 릴리스 실행 파일을 패키징하며 빌드하거나 실행하지 않는다. 압축 파일은 `dist/`에 생성되고 파일명에 버전, 운영체제, 아키텍처가 포함된다. 기존 압축 파일은 덮어쓰지 않는다. macOS는 `ditto`, Linux는 `tar`, Windows는 PowerShell `Compress-Archive`를 사용한다.

사용자 지정 대상 디렉터리나 실행 파일을 사용한다면 경로와 일치하는 아키텍처를 지정한다.

```sh
bash scripts/package-macos.sh path/to/ghost-chat-cleaner path/to/output aarch64
bash scripts/package-linux.sh path/to/ghost-chat-cleaner path/to/output x86_64
```

```powershell
./scripts/package-windows.ps1 -BinaryPath path/to/ghost-chat-cleaner.exe -OutputDirectory path/to/output -Architecture x86_64
```

아키텍처 인수는 제공한 실행 파일의 아키텍처를 표시하며 교차 컴파일을 수행하지 않는다. 셸 스크립트는 `x86_64`, `aarch64`, `arm64`를 허용하며, 마지막 값은 `aarch64`로 정규화한다. PowerShell은 `x86_64` 또는 `aarch64`를 허용한다. 기본값은 패키징을 수행하는 컴퓨터의 아키텍처다.

압축을 푼 뒤 실행 파일 또는 macOS 앱 번들을 실행한다. 압축을 푼 패키지에서 데모 모드를 사용하려면 다음과 같이 실행한다.

```sh
# macOS
"./Ghost Chat Cleaner.app/Contents/MacOS/ghost-chat-cleaner" --demo
# Linux
./ghost-chat-cleaner --demo
```

```powershell
# Windows
.\ghost-chat-cleaner.exe --demo
```

포터블은 설치 프로그램이나 백그라운드 서비스 없이 압축을 풀고 실행한다는 뜻이다. 패키지는 아키텍처별로 구분되며 운영체제의 그래픽·런타임 라이브러리에 의존한다. 범용 바이너리는 아니다.

### CI와 서명 없는 배포

[포터블 빌드 워크플로](.github/workflows/release-build.yml)는 Windows x86_64, Linux x86_64, macOS Apple silicon, macOS Intel을 대상으로 구성되어 있다. 풀 리퀘스트, `main` 푸시, `v*` 태그, 수동 실행 시 포맷 검사, Clippy, 가상 데이터 테스트, 릴리스 빌드, 패키징을 수행한 뒤 워크플로 산출물을 업로드한다. 작업이 구성되어 있다는 사실이 모든 운영체제의 실제 실행 검증 통과를 뜻하지는 않는다.

패키징 스크립트와 워크플로는 배포자 서명이나 공증을 제공하지 않는다. 압축 파일은 서명 없는 배포 산출물이므로 실행 전에 조직의 소프트웨어 정책을 따르고 출처를 확인한다. 이 워크플로에는 설치 프로그램, 백그라운드 서비스, 자동 릴리스 공개 기능이 없다.

## 유지보수와 의견 보내기

재현 가능한 문제나 개선 제안은 [GitHub Issues](https://github.com/AidALL/Ghost-Chat-Cleaner/issues)에 등록한다. 운영체제, 아키텍처, 빌드 또는 커밋, 정확한 오류 표기, 재현 절차를 포함한다. 가상 예시를 사용하고 계정 식별자는 가린다. 대화 목록 데이터베이스, 대화 제목, 저장된 브라우저 프로필, 인증 정보, 비공개 원본 로그는 첨부하지 않는다. 프로젝트 작성자는 garlicvread이며, 비공개 문의는 [ceo@aidall.tech](mailto:ceo@aidall.tech)로 보낼 수 있다.

브라우저 호환성 변경 시 [관찰된 계약](docs/browser-contract.md)과 수집기 테스트 데이터를 함께 갱신해야 한다. 빌드나 가상 데이터 테스트의 성공만으로 인증된 환경의 실행 호환성이 입증되지는 않는다.
